# `.github/` Directory — Midstream Ownership Policy

The `.github/` directory is a Midstream-owned integration boundary. During an
upstream sync, ignore changes under `.github/` by default. Do not automatically
add, update, or delete files in this directory to match
`vllm-project/vllm-omni`.

This difference from upstream is expected. GitHub Actions, repository policy,
templates, and automation must match the Midstream repository and its release
process rather than silently inherit upstream behavior.

## Workflows allowed to run

The Midstream repository runs only these reviewed workflows:

- `.github/workflows/fork-sync-review.yml`
- `.github/workflows/omni-release.yml`

Upstream workflows, including `build_wheel.yml` and `pre-commit.yml`, are not
carried. Their responsibilities are either unnecessary in Midstream or owned by
the Midstream release and nm-cicd integration above.

## Adopting an upstream change

An upstream `.github/` change may be adopted only as an explicit Midstream
change with a named owner, review, and repository-specific validation. Once
adopted, the resulting file is Midstream-owned; later upstream changes are not
merged automatically.

Sync reviews should report upstream `.github/` differences as intentionally
ignored rather than as missing source carries.
